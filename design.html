Predictive Execution Cockpit — Full Design Document

1. System Purpose

The Predictive Execution Cockpit provides a real-time operational view of an execution engine. It visualizes:

  • Regime state
  • Risk / Impact / Slippage / Latency
  • Arbitration & federation decisions
  • Anomaly detection
  • Event timelines
  • Quadrant classification
  • Sync drift
  • Heartbeat

The system is model-agnostic, data-agnostic, and deployment-agnostic.

2. High-Level Architecture

2.1 Components

  • Backend API (FastAPI): Provides metrics and decision logic via JSON endpoints.
  • Frontend Cockpit (Static HTML/JS): Polls backend every second and renders panels.
  • Deployment: Backend as Web Service, frontend as Static Site, communication via HTTPS + CORS.

3.3 Core Logic

Risk:

risk = clamp(0, 1, 0.35 + sin(t/8)*0.25 + noise)

Impact:

impact = clamp(0, 1, 0.40 + cos(t/10)*0.20 + noise)

Slippage:

slippage = clamp(0, 1, 0.30 + sin(t/6)*0.30 + noise)

Latency:

latency = max(1, 12 + sin(t/4)*6 + noise)

Regime Mode (OK/WARN/CRITICAL):

score = (risk + impact + slippage) / 3

if score < 0.33: mode = "OK"
elif score < 0.66: mode = "WARN"
else: mode = "CRITICAL"

Federation: returns model outputs and selected model (model1/model2/model3).

Arbitration: returns final_mode based on mode.

Anomaly Detection:

risk_spike    = risk > 0.85
impact_jump   = impact > 0.85
slippage_jump = slippage > 0.85
latency_spike = latency > 20

Quadrant:

LOW:     risk < 0.33 AND impact < 0.33
MEDIUM:  risk < 0.66 AND impact < 0.66
HIGH:    risk < 0.66 AND impact >= 0.66
CRITICAL: else

Sync Drift:

drift_ms = random(0..250)
status   = "OK" if drift_ms < 120 else "DRIFTING"

Heartbeat: returns { alive: true, timestamp }.

5.5 Data Flow

const BASE_URL = "https://predictive-execution-1.onrender.com";

async function fetchJSON(path) {
  const res = await fetch(BASE_URL + path);
  return await res.json();
}

async function updatePanel(id, path) {
  const el = document.getElementById(id);
  el.textContent = JSON.stringify(await fetchJSON(path), null, 2);
}

function tick() {
  updatePanel("state-json", "/state");
  updatePanel("decision-json", "/decision");
  updatePanel("federation-json", "/federation");
  updatePanel("arbitration-json", "/arbitration");
  updatePanel("anomaly-json", "/anomaly_detector");
  updatePanel("events-json", "/node_events");
  updatePanel("quadrant-json", "/quadrant");
  updatePanel("heartbeat-json", "/heartbeat");
  updatePanel("drift-json", "/sync_drift");
}

setInterval(tick, 1000);
tick();

6. Deployment Design

6.1 Backend (Render Web Service)

  • Build Command: pip install -r requirements.txt
  • Start Command: gunicorn server:app --worker-class uvicorn.workers.UvicornWorker
  • Files: server.py, requirements.txt
  • Health Check: /heartbeat or /

6.2 Frontend (Static Site)

  • Publish Directory: repo root or frontend/
  • Files: index.html, style.css, dashboard.js
  • BASE_URL: points to backend URL.
